# 美妝電商 SQL 專案：BigQuery 操作步驟

資料集：Kaggle「eCommerce Events History in Cosmetics Shop」（10/2019 – 02/2020）

你的介面是簡體中文，下面引號裡的按鈕名稱都**逐字對應畫面上的字**，只是寫成繁體。

---

## 資料夾內容

```
sql-beaute/
├── bigquery/        ← 主要版本：在 BigQuery 執行
├── duckdb/          ← 備用版本：在自己電腦上用 DuckDB 執行
├── split-csv.ps1    ← 把 CSV 切成 100 MB 以下的小檔
├── .gitignore
└── 使用說明.md
```

---

## 第一步：下載並切分資料（在你的電腦上）

1. 到 Kaggle 下載資料集（需要登入），解壓後把 5 個 CSV 放進 `sql-beaute\data\`。
2. 在 `sql-beaute` 資料夾的空白處按住 Shift 再按右鍵，選「在終端中開啟」或「在此處開啟 PowerShell 視窗」。
3. 輸入：
   ```
   powershell -ExecutionPolicy Bypass -File split-csv.ps1
   ```
4. 完成後會多出 `upload\` 資料夾，裡面是 `2019-Oct_part01.csv.gz` 這類檔案，每個都在 90 MB 以下，而且每個檔案都保留了標題列。畫面最後會列出所有要上傳的檔案。

> BigQuery 網頁上傳的單檔上限是 100 MB，所以要先切分。`.gz` 是壓縮檔，BigQuery 可以直接讀取，檔案數量也會少很多。

---

## 第二步：建立資料集

1. 先按右上角的 **×** 關掉「查看 Studio 的新變化」視窗。上方黃色的「升級」**不要按**，沙盒版免費就夠用。
2. 左側清單找到你的專案 **clear-veld-411615**，按它右邊的 **⋮**，選「**創建數據集**」。
3. 填寫：
   - 數據集 ID：`beaute`（**一定要用這個名字**，SQL 檔裡寫的都是 `beaute.`）
   - 位置類型：「多區域」→ **EU**
4. 按「創建數據集」。

---

## 第三步：上傳資料（每個檔案重複一次）

**第一個檔案：**

1. 展開專案，在 **beaute** 右邊按 **⋮** →「**創建表**」。
2. 「從以下來源創建表」選「**上傳**」，按「瀏覽」選 `upload\` 裡的第一個檔案。
3. 文件格式：**CSV**。
4. 表名稱：`raw_events`
5. 「架構」：打開「**以文本形式修改**」，把預設內容刪掉，貼上下面這一行：
   ```
   event_time:STRING,event_type:STRING,product_id:INTEGER,category_id:INTEGER,category_code:STRING,brand:STRING,price:FLOAT,user_id:INTEGER,user_session:STRING
   ```
   **不要勾選「自動檢測」**，時間欄位要用文字讀進來，SQL 會再轉換。
6. 展開「**高級選項**」：「要跳過的標題行」填 **1**。
7. 按「創建表」。

**其餘每個檔案：**

同樣在 beaute 按 ⋮ →「創建表」，步驟 2 到 6 都一樣，只多一個設定：
「高級選項」→「寫入偏好設置」改成「**附加到表**」。

> 如果漏改這一項，會出現「表已存在」的錯誤，資料不會被覆蓋，改好再按一次就好。

**全部上傳完之後，檢查筆數：** 按上方藍色的 **+** 開新查詢，執行：
```sql
SELECT COUNT(*) FROM beaute.raw_events;
```
結果應該等於 PowerShell 顯示的 5 個月 lines 加總。

## 第四步：執行 SQL

每個檔案的做法都一樣：按 **+** 開新查詢分頁，打開 `bigquery\` 裡的檔案，全選複製貼上，按「**運行**」。

一次執行多段查詢時，下方會列出每一段的結果，按各段的「**查看結果**」就能逐一查看。

| 順序 | 檔案 | 內容 |
|---|---|---|
| 1 | `00_setup.sql` | 清理資料，建立 `events`、`orders` 和價格區間函式（**一定要先跑**） |
| 2 | `01_data_quality.sql` | 資料品質：缺值、重複、價格分布 |
| 3 | `02_funnel.sql` | Q1：轉換漏斗 |
| 4 | `03_cart_abandonment.sql` | Q2：購物車放棄 |
| 5 | `04_cohort_retention.sql` | Q3：同期群留存 |
| 6 | `05_seasonality.sql` | Q4：高峰日 |
| 7 | `06_first_purchase.sql` | Q5：首購與回購 |
| 8 | `07_chart_tables.sql` | 建立做圖表用的小表（要在 04 和 05 之後跑） |

---

## 第五步：跑完 01 之後回頭調整

1. **價格區間**：`00_setup.sql` 第 3 步的切點（2、5、10、20）是暫定的。改成 `01` 第 4 步算出的 p25、median、p75，再重跑 `00`。
2. **清理規則**：`00` 刪除了完全重複的列和價格 ≤ 0 的列。看 `01` 的數字確認合理，並把刪了多少列寫進 README。
3. **門檻**：品牌分析的門檻（1,000 個瀏覽 session、500 次加入購物車、200 位首購顧客）依實際資料量調整。

---

## 第六步：把結果拿去做圖表

1. 開新查詢，執行 `SELECT * FROM beaute.chart_daily`（或 `chart_brand_funnel`、`chart_cohort`）。
2. 結果上方按「**保存結果**」→「**CSV（本地文件）**」。
3. 在 Tableau Public 匯入 CSV 做圖：
   - 每日營收與 7 日移動平均（折線圖，標出高峰日）
   - 同期群留存（熱力圖）
   - 品牌轉換率與平均值的差距（橫條圖）
   - 轉換漏斗（長條圖）

## 沙盒版要注意的事

- **資料表 60 天後會自動刪除**：沙盒的限制。SQL 檔都在你電腦裡，重新上傳就能重跑，但最好在 60 天內把結果和圖表做完。
- **儲存上限 10 GB**：如果空間不夠，可以在跑完 `01` 之後刪除 `raw_events`（在表的 ⋮ 選「刪除」），後面的分析只會用到 `events`。
- **每月免費查詢 1 TB**：這個專案大約只會用掉幾十 GB。
- **如果 `.gz` 檔上傳失敗**：改用 `powershell -ExecutionPolicy Bypass -File split-csv.ps1 -NoGzip` 產生沒有壓縮的 `.csv` 小檔，檔案會比較多，但一定能上傳。
- **如果建立函式（FUNCTION）時出錯**：告訴我錯誤訊息，我把它改成直接寫在查詢裡。

## README 要誠實寫出的假設

- **沒有訂單編號**：一個含有購買事件的 session 視為一筆訂單。
- **資料從 10/2019 開始**：10 月的「新客」可能包含之前就買過的顧客。
- **時間是 UTC**：商店所在國家不明，高峰日由資料找出，不預設為黑色星期五。
- **回購只看 60 天**：只納入 2020 年以前首購的顧客。

每一個發現都要接一句「所以品牌應該怎麼做」，這是和其他 Kaggle 作品拉開差距的關鍵。
